# ADR-0001 规划模型为 MILP，四包共用一个模型

- 状态：已决（2026-10-29，07 Q02，09 D11）；B01 冻结
- 影响分支：B09、B10、B11、B12、B13、B28、B41

## 决定

规划模型是混合整数线性规划（MILP），**不称纯 LP**，也不论证“LP 松弛等价”。

- 储能充放互斥：二进制变量 `u[t]`，`pc[t] ≤ Pmax·u[t]`，`pd[t] ≤ Pmax·(1−u[t])`（B11）。
- 工序开始时段：独热二进制变量 `x[s]`，只为能完整放进允许窗口的 `s` 建变量，`Σ x[s] = 1`（B13，多工序 B28 扩展依赖/设备/交期）。
- 一个共享模型：B09 唯一拥有时间集合、购/售电、总负荷、公共功率平衡与总目标；四个包只经 `ModelBuilder`（`ports.ModelBuilder`）贡献变量、约束、平衡项与成本项。包不得自建模型、直接设目标、设置求解参数或读写其他包的变量。
- `add_constraint` 的 `refs` 必填（规则 ID、`config://` 配置项或资产版本至少一个），动作由此带上依据，供 Explainer 使用。

## 求解与状态

- `SolverBudget`：`time_limit_s`、`mip_rel_gap`、`threads`、`random_seed`，数值放配置。默认日前 20 秒 / 1e-3 / 单线程；一周与回测 300 秒。
- 求解只在 JobRunner 后台任务中执行（ADR-0006）。
- 求解后先把二进制变量取整、把 |功率| ≤ 1e-6 kW 的值置 0，再独立校验平衡、上下界、整数性与互斥；未通过返回 `error`。
- `SolverStatus`：`optimal`（达到配置 gap，不表示已证明全局最优）、`feasible`（触及预算的可行解，附实际 gap）、`timeout`（无可行解，不返回计划）、`infeasible`（附冲突线索，不放宽硬约束）、`error`。只有前两者带计划，契约校验强制。

## 理由

工序整段平移与充放互斥本质是离散决策；本机实测 HiGHS 1.15.1 日前 96 时段 1 道工序 0.37～0.48 秒、5 道链式工序约 1 秒，MILP 在预算内。四包各自规划再拼结果会破坏功率平衡与账本守恒。

## 后果

- `PlanResult` 必须带求解器名称/版本/参数、gap、目标值与下界、耗时、分项目标。
- grid_export 上限由配置给定，骨架为 0（07 Q16 待讨论）。
