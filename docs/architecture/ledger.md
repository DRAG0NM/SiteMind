# 电量账本（B08）

`plantkg/core/ledger.py` 是账本的唯一权威计算（03 §2.4）。规划器（B09）和储能包（B11）可以在模型里写同样的约束，但费用、SOC 和守恒的结论只认这里；状态写入统一由执行器（B16）负责。

## 口径

每个时段（交流侧，非负量）：

```text
光伏使用 + 购电 + 放电 = 负荷 + 充电 + 外送
光伏使用 + 弃光 = 光伏可发
E[t+1] = E[t] + η_c·充电功率·Δt − 放电功率·Δt/η_d        SOC = E / 容量
费用 = 购电电量 × 该时段电价        峰值 = 最大购电功率（只作指标，不进目标）
```

- 输入功率为时段平均 kW；电量 kWh = kW × 时段小时数（按区间实际时长算，不按时段个数），时段必须等长且首尾相接。
- 弃光：计划或执行给了就用；没给按“光伏优先”推导（光伏先供负荷、充电与外送，剩余需求由放电补，最后购电）。外送上限为 0 时光伏多余即弃光。
- 购电：计划或执行报出了就拿来复算残差；没报出按差额推导（此时能量平衡在构造上成立，只靠它不能证明账本正确，见下“验收”）。
- 期末电量：执行器报出了（`reported_energy_end_kwh`）就与重算的 SOC 递推核对，超 1e-3 kWh 记问题。
- 缺电价记为费用未知（`None`），不当 0；总费用也为 `None`，账本判为不平。
- 容差：契约 `LEDGER_TOLERANCE`（`ledger-tol-1`，07 Q16）；计划账本费用与模型目标值比对用 `COST_TOLERANCE`（`ledger-cost-tol-1`：max(0.01 元, 1e-6 × |目标|)）。两者冻结测试前不得改。

## 接口

| 函数 | 作用 |
| --- | --- |
| `compute_ledger(slots, meta, storage, energy_start_kwh, objective_value_cny=None)` | 逐时段重算，返回契约 `Ledger`（`balanced` 只在无任何问题时为真）与问题清单、各项总电量 |
| `validate_balance(ledger, objective_value_cny=None)` | 复核别人交来的账本：契约层复核（能量、SOC 递推、连续、互斥）+ 费用按“购电 × 电价”另算 + 峰值重算；给出目标值时重算 `objective_gap_cny = 总费用 − 目标值` 并按费用容差判断（B09/B17 用） |
| `replace_shifted_load(total_kw, operations, slot_hours)` | 总表扣除各工序原时段曲线、再加到新时段；扣出的负残余超过 1e-3 kWh 即拒绝（分表不属总表或重复计量），容差内的微小负值截为 0；返回新总负荷与不可平移负荷，总电量（容差按时段数累计）与每道工序电量守恒 |

`LedgerMeta.kind` 只能是 `plan` 或 `execution`，`source_refs` 不能为空，入口即校验。B0/B1/B2 的策略不记在账本里，经 `plan_id` 对应的计划（`Plan.policy`）区分。
| `ledger_summary(ledger)` | `ledger` 工具与工作台用的摘要（≤ 8KB，不含逐时段明细） |

计划账本与执行账本分开（09 D30）：计划账本用预测输入，费用应与模型目标在容差内一致；执行账本用回放实际数据，与计划之差记为预测偏差，不比对目标值。B0/B1/B2 三种策略都用同一套函数核算。

## 判为不平的情况

同时充放、SOC 越界、报出的购电与重算不符（残差超容差）、报出的期末电量与重算不符、供给超过需求（放电或光伏无处可去）、弃光超过可发、弃光同时购电（两者都超过 1e-3 kWh；弃光同时放电可由执行削减产生，合法）、无储能却有充放、缺电价、计划账本费用偏离模型目标。输入为负、非有限数、时段不连续或不等长、初始电量越界、SOC 上下限颠倒、账本类型或来源缺失，直接抛 `PLANTKG_E_DOMAIN_INVALID`。

规模：一周 672 个 15 分钟时段、负荷约 1 MW、储能 1 MWh 下，7 次充放往返后电量无漂移（测试 `test_week_scale_numerically_stable`）。

## 验收依据

手算三时段（`fixtures/ledger/hand_calc_three_slots.yaml`，算式写在注释里）逐项核对电量、费用、SOC；上面每种不平情况各有反例；平移守恒与重复计量反例；200 组随机一致调度全部判平、复核为空。

## 与其他分支的衔接

- B16 执行器：把确认计划的充放、弃光与回放实际数据组装成 `SlotInput`，调用 `compute_ledger` 得执行账本；执行削减（先弃光、再削减放电）由 B16 决定，账本只核算结果。`LedgerCalculator` 端口的组装实现归 B16。
- B13/B14：预测的是不可平移负荷（07 Q25），计划账本的负荷 = 不可平移预测 + 各工序按计划起点放置的曲线；执行账本用 `replace_shifted_load` 平移当天实际设备曲线。
- B17：B0/B1/B2 对照与计划账本、模型目标一致性检查都调用本模块。
