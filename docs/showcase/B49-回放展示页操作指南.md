## 3. 数据契约与回放规则

- 唯一数据来源是加载进来的 `day.json` 与播放头 `cursor`。页面不各自维护回放状态，也不用叙事文字硬编码数字。
- 可见时间：事件、工单、裁决、知识版本、问答、资产都按各自时间字段裁剪到 `cursor` 之前；提案与 Agent 运行按「仿真结果可见时刻」裁剪，优先 `timing.effective_at`，其次 `binding.trigger_at`、`timing.trigger_at`、`timing.origin_event_at`。`requested_at` / `returned_at` 是墙钟，不参与比较。整次运行生效前不露工具明细与最终回答，生效后整段可见（工具 `started_at` 可能是墙钟，不逐条比较）。裁决除要求 `decision.at <= cursor` 外，还要求它引用的提案结果都已可见。资产看 `available_at`，证据看 `occurred_at`。往回调播放头时，先前点开的问答、运行记录与判读结论会自动失效，不显示未来的回答。
- `null` 不折算成 0：指标取值为 `null` 或缺失时页面显示 `—` 与缺失说明，不参与比较。
- 数据性质保留：`measured / derived / configured / simulated / synthetic` 原样展示；样例的问答与指标统一标「演示场景」，页头注明「含合成补全」，不冒充真实 Nexent 调用。
- 关联只用正式字段：提案、裁决、问答、运行记录之间靠 `decision_id`、`proposal_ids`、`ticket_id`、`agent_run_id`、`evidence_refs` 匹配，不靠文本相似度猜。
- 16:00 的知识发布与运行分叉按 `runs` 接续链（`RunChainEntry`）展示，页面不凭空造分支。
- 本次为读 `assets` / `evidence` 在 `types.ts` 里追加了可选字段，并在 `validate.ts` 的数组与时间字段表里登记；旧 day.json 没有这两节时按空数组处理，加载不受影响。

## 4. 各页现在能看到什么

**总览 / 舞台**：2.5D 轴测厂区图、事件、泳道与播放条由 #208 实现，本次未改。

**主 Agent**：候选方案对比表、冲突 → 换算 → 裁决链条、快/慢通道标识、慢通道追问、自主等级矩阵沿用 #208。本次改问答面板：
- 预设问题只来自 `day.qa` 中 `cursor` 之前真实存在的记录（取最近 4 条），不再混入示例问题；
- 没有 `qa` 时显示「当前时刻暂无问答记录，请推进播放条查看后续交互。」；
- 气泡标出来源（演示场景 / 无运行记录关联 / 运行记录未导出），空回答与缺失证据分别提示。

**资料与图谱**：
- 资料卡按四态着色并给出计数：沉睡 → 已标识 → 已入图 → 被引用；有 `day.assets` 时额外显示真实资产清单（标题、可用时刻、阶段），阶段由 `sources[].asset_version_id` 的证据事件类型推断（retrieval→已标识、graph_query→已入图、rule_lookup/rule_applied/plan_created/version_activated→被引用）；
- 资产激活率仍取「被引用 / 总数」，标准对齐率读 `standard_alignment_rate`，缺失显示「当前快照暂未包含对齐率指标」；
- 图谱新增「开场 → 插曲资料入库 → 纠错附资料」三阶段卡片，阶段时刻由当天实际的事件单、资料入库事件与知识版本激活时刻切分，未到的阶段置灰，不预画未来节点；资料节点用中文书名而不是内部编号。

**效果对比**：原有三组 × 六项设备指标保留，新增四块：
- 知识侧：资产激活率、标准对齐率、本体与规则抽取 F1、构建效率、跨文档问答正确率与普通 RAG 对照（`group=knowledge`），缺失时给出「当前快照暂未包含知识侧评测指标」的空态；
- 编排对照：全程序派发（关闭慢通道）与快慢双通道的 10~20 起未见事件（样例 16 起），对比处理正确率、证据完整率、平均研判耗时，两个口径并列，不预设谁更优；
- Harness：行为回归集通过率、平均工具调用次数、平均耗时，按指标名 `@版本` 后缀分行；只有一次重跑结果时显示单次并注明「累计多版本回归记录后自动生成趋势曲线」，不画假趋势；
- 越学越省：按资料批次看 Agent 段占比与每百条复核分钟，单批次不连线。

**四位专家页（电梯 / 能源与储能 / 暖通 / 设备监测）**：域内状态与动作沿用 #208。设备监测页新增「传感器读数质量」面板：
- 报警读数（`quality`、`residual_c`、`residual_limit_c`）、候选故障假设与已排除项、交叉验证依据、Agent 试探过程（工具调用顺序、耗时、状态、结论）与最终判读；
- 演示场景把「传感器读数异常」放在 15:10（`event://demo-sensor-lie`），15:18 交叉核对后判为探头漂移；真实导出没有质量分与残差字段时显示「当前时刻暂无传感器读数异常事件」的空态，不生成读数。

**Nexent 运行记录抽屉**：新增「关联事件单」「Agent 调用层级」（按 `depth` 缩进，标 L0/L1… 与耗时）、工具行的执行 Agent 与业务状态、最终回答；运行记录同样按播放头裁剪，不展示未来的运行。

## 5. 启动与验收命令（Windows PowerShell）
```powershell
cd .\SiteMind\web
npm ci
npm run dev:showcase        # 浏览器打开终端给出的 /showcase.html
```

离线单文件（可直接双击、`file://` 打开）：

```powershell
cd .\SiteMind\web
npm run build:showcase
# 产物：web\dist-showcase\index.html
```

带真实导出的回放：

```powershell
# 仓库根目录
python -m plantkg.world.scenario export-day --run-id <run_id> --out runtime\days\<run_id>.json
python -m plantkg --profile mock          # 默认 127.0.0.1:8700
# 展示页地址后加 ?run_id=<run_id>，加载失败会回退到同目录 day.json 或标准演示场景并说明原因
```

工程验证：

```powershell
cd .\SiteMind\web
npm test
npm run build:showcase
npm run build
```

## 6. 已知限制与上游待接

- 知识侧六项指标、编排对照、Harness 重跑与学习曲线目前是**标准演示场景的 synthetic 值**（`note` 已写明「合成演示，待实测数据替换」）；B33/B36 产出真实 `metrics` 后按同名指标自动生效，无需改页面。
- 组装后的接续版本、版本化重跑与跨批次曲线由 B48/B27 的数据生产端提供；只有单点数据时页面只显示单次。
- 资产四态优先用导出的 `assets` + `evidence`；B36 目前尚未把资产全量写进 day.json，因此真实导出多数情况下会走「按资料卡近似 + 文案说明」的分支。
- 运行记录里 MCP 工具级的 `call_id` 与实时问答证据关联仍受 #214 影响；本页只展示已有字段。
- 未做分支推演、场景切换与真实业务写入，均为 B49 范围之外。
