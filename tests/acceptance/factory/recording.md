# B36 离线演示与录制（视频尚未录制）

默认入口执行 B32/B47 正式业务逻辑。事件和复核员操作为 synthetic；回测、待确认动作、确认发布、规则匹配及执行判断均由领域服务实际完成。预设问答标为模拟回答，未调用真实 Nexent。

1. 在仓库根目录运行 `python scripts/demo_factory.py --mode offline --out <不存在的输出目录>`。默认种子为 20260701，入口固定 Python 哈希种子，且仅在 B36 场景中按时间、事件单、类别和摘要对待汇报事项稳定排序，以避免 #262 的随机绑定。该排序保留全部事项和原有门控，不修改公共路由器。结果包含两日 day.json、trace.json、scenario.db、correction.json、B33 evaluation/ 及缓存统计。每次使用独立目录；不覆盖旧结果。
2. 第二次用相同命令和不同输出目录运行。设置 `B36_RUN_A`、`B36_RUN_B` 和 `B36_REAL_RUN` 为对应目录，执行 `python -m pytest tests/acceptance/factory -q -rx`。完整记录仍保留；#262 的已知文本排序差异单独显示为 xfail，任何状态、账本、提案、授权和事件关联差异仍导致失败。
3. 在 web/ 中复用已有依赖，缺少时执行 `npm ci`，再执行 `npm run build:showcase`。断开后端后打开 dist-showcase/index.html，导入第一日 day.json；第二日导入 day-2026-07-02.json。
4. 自动截图：`node tests/acceptance/factory/capture.mjs web/dist-showcase/index.html <第一日 JSON> <第二日 JSON> <新截图目录>`。脚本使用本机 Chrome 的 DevTools，检查 08:05、16:00 组合异常、16:10 发布分叉、次日事件、Agent 记录、预设问答及效果页电费差额。
5. 录屏时用窗口录制工具并导入 subtitles.srt。素材顺序：07:30 资料；08:05 能源及电梯；09:30 手册；10:30 多专家；12:30 临时指令；14:20 工单及 14:30 确认；16:00 未知异常；16:10 B32 发布；次日 16:00 规则复用；最后展示 B33 对照。自动截图脚本不生成视频。工作台 Nexent 现场段须另获模型费用授权，当前尚未录制。

B33 对照通过官方 evaluate/cache/refresh 接口离线采集，保留正式 v1 缓存和来源信息。它使用独立两日运行及评测末端充电规则，未执行 B36 的人工纠错复核流程；因此它是 B33 三组之间的效果对比，不能解释为本次 B36 回放相对基线的收益。不可比数据不展示改善率。

PR #261 已提供正式规则消费及版本化授权接口。旧 `--mock-issue-260` 参数与适配器已移除。correction.json 保存实际 B32 候选、回测、确认、发布版本，以及跨版本、设备、条件和整份提案授权的真实检查结果。

Issue #262 上游公共实现尚未修复。未启用 B36 稳定排序的运行曾出现同分钟合批文本顺序和首个绑定事件单变化；本演示通过局部装配消除这一差异，并对两次运行的完整业务记录和关联做比较。对上游通用实现不声称已修复或完成完整确定性验收。
