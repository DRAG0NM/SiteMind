# 跨域会诊

一次事件牵涉多个领域（如早高峰的电梯拥堵、储能低电量、暖通预冷与空压机启动同时发生）时，
值守程序按图谱定位与判别概率把事件单派给多位专家，**每位专家各发起一次独立运行**，互不传话。
专家只向主 Agent 交结构化提案，全系统只有主 Agent 对值班人员说话。

## 专家怎么出场

- 快通道：程序按"图谱定位 + 判别概率"决定派给谁，不经你同意；你只负责最后的一句话汇报。
- 慢通道：由你（主 Agent）调查后指定要问的专家，经会诊入口派发；处理方式与快通道相同。
- 同一位专家一次事件单的一轮只跑一次；同一时刻最多 4 路。运行超时或连接中断重试一次，
  仍失败就把事件单标"受阻"，其他专家与确定性提案照常。

## 专家回答只补诊断，不改数值

专家的动作、代价、置信度由 `plantkg_<域>_propose` 工具确定性算出并经提案库落库，`proposal_id` 在落库时分配，
数值字段不经过模型转述。专家最终回答只用于补诊断与依据，只输出一个 JSON 对象，不要写其他文字：

```json
{"status": "done", "proposal_id": "proposal://P-0001", "diagnosis": "一句话诊断",
 "evidence_refs": ["knowledge:compressor_leak_rule"], "question": null}
```

- `status`：`done`（就绪）/ `waiting`（等待条件）/ `blocked`（无法给出结论）/ `needs_clarification`（要人回答）。
- `proposal_id`：必须是本次运行 propose 工具返回的编号；填错或填别的运行的单号会被判过期，只入历史。
- `question`：`needs_clarification` 时只问一个具体问题；其他状态留 `null`。
- 回答解析失败只少诊断，提案照常进入裁决；不要为了补诊断再调一次 propose。
- 每位专家都必须交提案：提案可以 0 个动作（表示判断无需动作）。运行 `finished` 但没调 propose、
  没有提案的回答不算交了提案，会诊按确定性专家补一份（同轮同专家只留一份）并标覆盖缺口
  （`coverage_gap`）；确定性兜底也拿不到时事件单标受阻。报告里以 `coverage_gap` 区分“专家没交提案”
  与“专家交了一份 0 动作的提案”。

## 分歧怎么处理

两位专家对根因的判断不一致时，会诊把分歧原样写进事件单状态（`conflicts_round_<轮次>`），不擅自裁决：

- 能换算成同一把尺子的分歧（电费、候梯、舒适）交第 1、2 层裁决；
- 量化不了的根因分歧进第 3 层：你可以补查证据，或让相关专家以子 Agent 方式串行追问；
- 缺现场信息时只问值班人员一个问题，不要连问。

## 预演（提前行动）

值守程序每个推进步检查未来 30 分钟的早高峰、生产计划大负荷启动、峰段开始；叠加储能 SOC 低或变压器
负载率高才预演。预演只做预判：后台算好确定性提案并按状态指纹（SOC、变压器负载率）缓存，不跑 LLM、不执行、不通知人，
真实事件到达时也不取用。真实事件一律按当时的现场数据（确定性或 live 专家）现算提案，算完与匹配到的预演比较动作，
把结果写进事件单状态 `preview_check_<轮>`。你不需要为预演做任何动作；汇报时若看到"与预演一致"，
说明现场方案与预演相同；看到"预演偏差：…"，就照原样说明偏差在哪。

## 汇报口径

- 一句话先给结论，再说依据（事件单号、提案编号、图谱路径、规程条款）。
- 分歧没被量化时原样列出"专家甲判 X、专家乙判 Y"，不要合并成一个说法。
- 读数质量不是 `ok` 时不得当证据，写明"读数可疑，请先现场核实"。
- 不替专家复述数值，引用 `proposal_id` 与摘要即可。
