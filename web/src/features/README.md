# B35 工作台视图：证据、处置卡片、数字对比与图谱生长

控制台（`web` 根目录，`npm run dev`）新增两屏和两组卡片。所有视图先读真实接口，读不到就退回演示数据，并在界面上标出数据性质（实测 / 推算 / 仿真 / 合成）。

## 怎么看效果

1. 装依赖并起控制台：`cd web; npm install; npm run dev`，打开 http://127.0.0.1:5173 。不起后端时全部走演示数据，界面显示「合成」与退回原因。
2. 处置席（键盘 3）：左栏分「批准 / 工单 / 抽查 / 纠错 / 回答 / 发布」六组。选中一条，中栏换成对应卡片：
   - 工单卡显示来源是伤亡还是重大损失、已自动执行的预案保护动作，点「已到场确认」；
   - 纠错卡填一句话纠正（可选步骤、可选资料），提交后显示进化时间线；
   - 抽查卡判对 / 判错，判错可勾「不是系统判断有误」；
   - 批准卡可填原因后批准或驳回；回答卡填主 Agent 那个问题的答案。
   - 标题旁「查看证据」打开四段证据抽屉：模型填值 → 系统绑定值 → 图谱路径 → 原文片段；检索类冷蓝、推理类暖橙。右栏每台控制也有「证据」。
3. 数字对比（键盘 4）：基线组 / 独立组 / 协同组三列对比表、六张柱状图、复核量-F1 曲线。`/baselines`、`/review-metrics` 不通时退回演示数据。
4. 资料与图谱（键盘 5）：把 txt / md / json 拖进虚线框（或点框选文件），看进度、命中清单、图谱节点逐个长出。
5. 接真实后端：`python -m plantkg --profile demo` 起在 8700，开发代理会带上 `runtime/operator.token`。确认动作的复核员默认是 `u-reviewer`，demo 配置里是 `dev-reviewer`，两边不一致时用 `PLANTKG_ACTOR=dev-reviewer npm run dev`，否则确认端点返回 403，界面会显示原因并退回演示替身。

## 数据性质

- 真实接口（`/actions`、`/evidence`、`/plans/{id}/explanation`、`/assets/{id}/fragments`、`/baselines`、`/review-metrics`、`/evolution/timeline`）：实测或推算。
- 演示数据（day 记录合成、本目录 mock、拖入资料的本地匹配）：合成，节点和卡片上带徽章。

## 已知缺口

- 资料拖入没有上传接口，当前只做本地关键词匹配（Issue #232）。
- 抽查判错的「不是系统判断有误」只能记在前端处置记录，后端拒绝不接受修订（Issue #234）。
